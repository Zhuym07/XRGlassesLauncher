# XR Desktop

面向外接 XR 显示器的 Android 桌面与低亮度手机触控板，当前重点适配一加 13 / ColorOS。

**当前版本：0.4.7 · 版权所有 © 2026 Ckar**

发布构建、签名备份和升级说明见 [发布指南](docs/RELEASING.md)，本版更新见 [发布说明](docs/releases/0.4.7.md)。

## 用 Android Studio 打开

1. 在 Android Studio 中选择 **Open**。
2. 选择本目录：`XRGlassesLauncher`。
3. 等待 Gradle Sync 完成。
4. 使用 Android Studio 的 **Build > Make Project** 编译，或直接点击运行按钮安装到真机。

工程使用标准 Android Gradle Plugin 配置和 Gradle Wrapper，不依赖 Codex 的临时缓存扫描脚本。

## 环境要求

- Android Studio 2026.1.1 或兼容版本
- Android SDK Platform 36
- Android SDK Build-Tools 36.x
- JDK 21（Android Studio 自带 JBR 即可）
- 一加 13 真机，已开启 USB/无线调试

- 动态发现支持 Presentation 的外接显示器，不固定使用某个 display ID
- 尝试把本应用 launcher 和第三方启动器应用放到外屏

- 外屏 launcher 使用大屏 Material 3 布局，分为收藏、最近使用、全部应用三个区域，支持搜索、真实应用图标、长按收藏和启动状态反馈
- 外屏 launcher 顶部显示时间、display ID、分辨率和连接状态，适合 XR 眼镜观看距离
- 手机触控板仅底部左侧 1/3 为多任务热区，主体区域全部为触控板，单击优先打开绑定到外屏的临时悬浮窗，不切换当前外屏任务；ColorOS 拒绝外屏悬浮窗时自动回退到外屏 Activity 菜单
- 外屏 launcher 支持搜索、收藏优先、最近使用排序和网格密度设置
- 设置页支持收藏应用、排序、指针/滚动灵敏度、四指截屏开关、启动时自动打开 Launcher 开关，以及外屏重连后恢复上次应用开关
- 手机端和外屏均可选择应用，记录启动请求及无障碍可观察到的窗口位置
- 中文文本通过无障碍设置外屏已聚焦的可编辑输入框；失败时保留手机草稿
- 可选 Root 仅用于定向发送外屏返回键，不在启动时自动请求 Root

## 使用方式

1. 连接眼镜，打开 XR Desktop；「设置 → 启动时智能打开桌面」开启时，查询外屏实时窗口：没有活动应用才打开桌面，有第三方应用则保留画面，查询不可用时不盲目切换。上次应用历史不会被当作仍在运行的证据，可从主页选择继续应用或主动打开桌面。
2. 首次使用时只需在系统设置中启用 XR Desktop 无障碍服务，之后保持启用即可，不需要每次手动关闭或重新开启。
3. 重新打开手机端 XR Desktop 可进入黑色触控板；外屏 Launcher 仍会保持在眼镜上。
4. 单指移动光标，短按点击，连续短按双击；单指按住后移动拖拽。
5. 双指滑动滚动；手机触控板底部左侧 1/3 单击打开外屏最近应用菜单，底部右侧 2/3 短按操作外屏返回，主体区域全部用作触控板。菜单优先以外屏悬浮窗显示，关闭后当前应用继续保持在下方。
6. 文字输入从手机控制页的“文字输入”按钮打开；先在外屏点击目标输入框，再在手机输入并发送。
7. 外屏返回使用 Root 的 display-aware keyevent，仅发送到当前外屏，不占用手机音量键，也不会调用无 display 参数的全局返回。
8. 四指同时轻点截取外屏；成功后图片会出现在手机相册的 `Pictures/XRDesktop`。

无障碍光标是不可触摸的外屏覆盖层，点击与滚动是触摸手势，**不是系统原生鼠标**。不支持鼠标悬停、右键或真正的滚轮事件；第三方应用对触摸手势的支持决定其行为。不会用没有显示器参数的全局返回操作误操作手机。

## 权限与限制

- 需要 Root 时，首次执行 Root 操作会由 KernelSU 授权；Root 只用于发送带 displayId 的外屏返回键。
- 触控板、文字输入和外屏截图都依赖无障碍服务；详细状态可在「设置 → 诊断」查看。
- Android 10 及以上通过 MediaStore 写入应用自己创建的图片，不需要额外的“相册读取权限”；截图文件由系统媒体库写入 `Pictures/XRDesktop`。
- 如果希望菜单不打断当前外屏应用，建议授予普通悬浮窗权限；权限仅用于创建外屏临时菜单，不用于全局输入 Hook。未授予时仍会自动回退到外屏 Activity 菜单。
- 当前公开 API 原型不会自动修改 `force_desktop_mode_on_external_displays`，也不会启用 LSPosed Hook。
- 启动外屏应用时会使用外屏独立的显示上下文、真实分辨率和全屏任务边界，减少相机等应用沿用手机竖屏任务尺寸导致的比例异常；但应用自身锁定竖屏或不可调整大小时，系统仍可能保留黑边或竖屏布局。
- 如果系统报告外屏 `canHostTasks=false`，ColorOS 可能拒绝第三方任务真正驻留外屏；应用会保留失败状态，后续再根据日志做定向适配。
- 手机屏幕第一版保持点亮，但显示全黑低亮触控板；物理熄屏不作为当前验收条件。

## 当前版本补充

- 外屏返回命令必须使用 `input -d <displayId> keyevent KEYCODE_BACK` 的参数顺序；旧的 `input keyevent -d ...` 在部分 ColorOS 版本会返回成功但仍作用于手机。
- 手机控制页增加“测试截图”按钮，可先验证无障碍外屏截图和相册保存，再测试四指手势。
- 如果状态卡片显示“外屏截图能力：false”，说明系统没有给当前无障碍服务加载截图能力；此时只需在无障碍设置中重新绑定一次服务，不需要日常反复开关。

## 0.4.0 已知限制

- 设置数据当前使用应用本地持久化偏好保存；后续可以迁移为 Preferences DataStore，不影响现有键名。
- 四指截屏依赖 Android 无障碍服务的 display 定向截图能力；如果当前 ColorOS 拒绝该请求，会给出失败提示，不会自动申请 MediaProjection。
- 外屏 launcher 的收藏、排序、网格、灵敏度和自动启动/重连恢复设置仍使用应用本地持久化偏好，后续可无损迁移为 Preferences DataStore。
- 物理断线时 ColorOS 可能直接销毁外屏 task，普通应用无法阻止第三方 Activity 被系统移除；当前版本会记录断线前已确认的外屏应用，并在重连后按设置尝试恢复，失败时给出日志并可回到 Launcher。
- 外屏输入仍是无障碍触摸手势和覆盖层光标，不是原生鼠标，暂不支持悬停、右键或真实滚轮。
- 未把旧 Java Activity 删除；它们作为兼容回退实现保留，但 Manifest 默认入口已切换到 Compose Activity。

## 0.4.5 触控板分区与退出修复

- 主体区域全部用于触控板，左侧不再是贯穿全屏的多任务按钮。
- 左上角隐藏退出点击区、手机系统返回键均回到手机控制页并恢复窗口亮度，不向外屏发送返回。沉浸模式下可先从边缘呼出系统导航。
- 仅底部 96dp 为控制条：左 1/3 短按打开外屏多任务；右 2/3 短按（500ms 内）发送外屏返回。控制条不会移动外屏指针；长按、多指、滑动均不触发操作。
- 外屏返回继续使用现有的可选 Root 定向注入。Root 未授权/命令失败时显示失败反馈，绝不回退为手机的无障碍全局返回；未实现 Shizuku。
- 手机页与触控板保持同一个 Compose 根节点，不再反复替换 Activity 内容视图；退出时取消拖拽、清理输入与临时菜单、恢复亮度和系统 UI。
- 四指截图判定按每根手指的位移累计，移动取消后不因抬指重置；关闭截图、长按、第三根/第五根手指均不会误触发截图。
- 本轮单元测试覆盖二维区域边界、控制区点击/滑动/取消与四指轻点；真机 Back、拖拽和悬浮菜单仍需验收。

### 0.4.6 建议真机回归

1. 安装升级后，确认收藏与当前外屏应用仍保留。
2. 主页点击大按钮进入触控板：左上角不显示文字，轻点热区或系统返回仍能回主页，亮度正常恢复。
3. 检查主体移动 / 点击 / 拖拽 / 双指滚动，以及底部多任务 / 外屏返回分区未变。
4. 在设置切换「English / 简体中文 / 跟随系统」，检查手机、外屏桌面与应用菜单；不应自动顶掉正在运行的第三方应用。
5. 主页「选择外屏应用」应启动所选应用，设置中的收藏管理只更改收藏。
6. 查看关于页与离线许可，清理最近记录前有确认提示，当前应用和文字草稿不应丢失。
7. 断开外屏、关闭无障碍或撤销悬浮窗权限，验证禁用状态与备用菜单。

自动化构建与测试不能代替上述真机验证。

## 0.4.7 断线状态与返回点击修复

- 当前窗口状态和「上次外屏应用」历史分离；历史仅用于继续应用，不阻止桌面自动打开。
- 重连、新 display ID 和新启动请求都会废弃旧的验证/延迟恢复，防止旧回调把已销毁的应用标为运行中。
- 手机回到前台或外屏重连后，等待窗口稳定再查询无障碍实时窗口：有第三方应用则保留，有桌面/菜单不重复启动，无应用则按自动启动开关打开桌面；无法查询时不盲目抢占外屏。
- 底部右侧 2/3 改为返回点击区，移动、长按、多指取消；不再要求轻划。手机系统返回仍退出触控板。
- 外屏返回只使用指定 display ID 的 Root 命令，等待授权的超时延长，拒绝/超时不重复请求，不使用全局辅助功能返回兜底。
- 断线立即取消输入；应用历史和继续入口保留，但不宣称上次应用仍在外屏运行。

真机回归：连接眼镜并运行应用 → 拔插 → 确认不再把历史当运行状态；重开手机控制页确认不顶掉实际运行窗口；短按底部右侧确认外屏返回而手机仍在触控板，滑动/长按不应返回。Root 命令退出码为 0 仅表示已发送，实际返回效果仍需真机确认。
